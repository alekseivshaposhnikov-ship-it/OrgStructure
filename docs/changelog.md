# Changelog

## 2.29.0 (2026-08-27)
 - CR-014: стабилизирована геометрия connector lines. Для любого node с organizational children строится читаемая main vertical stem от нижнего центра карточки до children junction (junction в свободной зоне между parent и детьми); линии не проходят через interior карточек.
 - Connector assistant отделён от organizational children connector: короткая отдельная связь от нижней границы manager рядом с правым краем к верхнему центру assistant-карточки. Связи строятся на явных anchor points и рисуются до карточек.
 - Toggle collapse/expand привязан к layout-геометрии (`node.x + node.width/2`, `node.y + node.height + TOGGLE_GAP`), а не к переменной content height; для siblings одного row toggle controls имеют общий baseline.

## 2.28.0 (2026-08-27)
 - CR-013_assistant_fix2: layout резервирует реальную assistant-zone для manager с ассистентами. Высота row менеджера с ассистентом учитывает `assistantVerticalGap + assistant.height + assistantToChildrenGap`, поэтому sidecar-карточка и её connector полностью находятся выше следующего organizational row и не пересекаются с department cards и horizontal junction.
 - Для manager без ассистента дополнительная вертикальная зона не создается (behavior не меняется); несколько ассистентов образуют компактную sidecar-группу, зона рассчитывается по фактическому bounding box группы. Assistant по-прежнему не создаёт новый row/level и не меняет effectiveLayoutLevel/sub_level/parent-child hierarchy.
 - Новый layout-параметр `assistantToChildrenGap` (по умолчанию 28px); паттерн «под-справа» сохранён.

## 2.27.0 (2026-08-27)
 - CR-013_assistant: визуальное размещение ассистентов изменено на паттерн «под-справа» (sidecar). Ассистент позиционируется относительно карточки своего руководителя (локальные параметры `assistantHorizontalGap`/`assistantVerticalGap`), а не относительно ширины subtree — больше не уезжает далеко вправо при росте ветвей.
 - Ассистент является sidecar-node: не создает организационный уровень, не меняет row/effectiveLayoutLevel/sub_level и parent-child hierarchy дочерних подразделений; несколько ассистентов одного руководителя образуют компактную группу; при collapse руководителя ассистент скрывается вместе с веткой.
 - Уточнены привязки ассистентов верхнего уровня: Селиванов → Давыдова, Лукьянов → Волкова, Клюев → Лихачева, LEGENDA Comfort / Мишуев → Николаева.
 - LEGENDA Comfort: руководителем карточки является Мишуев Александр Адольфович (presentation override по department_guid); промежуточный уровень «Клюев → Мишуев → LEGENDA Comfort» не создается; исходное API-дерево не мутируется.

## 2.26.0 (2026-08-27)
 - Обновлённые требования CR-013_fix: `LEGENDA Comfort` теперь подразделение Клюева (mapping по стабильному department_guid; внутренняя hierarchy не hardcode и строится по обычному API tree).
 - Обновлены presentation-титулы executives в конфигурации: Винник — «Директор по развитию градостроительной подготовки проектов», Клюев — «Исполнительный директор Холдинга LEGENDA».
 - Универсальная привязка ассистентов: персональный или административный ассистент привязан к своему непосредственному руководителю (подразделению, в чьих sourceUsers/users он находится) и визуально располагается рядом с его карточкой, не создавая отдельного организационного уровня. Несколько ассистентов разных руководителей работают одновременно; глобальное правило «первый ассистент в ветке → рядом с root» удалено.
 - Debug-диагностика department mapping дополнена полем match type (guid | name | fallback).

## 2.25.0 (2026-08-27)
 - Исправлен поиск top-management в holding leadership projection (CR-013_fix): руководители с дробной занятостью (count < 1) больше не теряются. В нормализации `transformNode()` сохранён полный исходный набор `sourceUsers` (до визуальной фильтрации по `count >= 1`); проекция индексирует `sourceUsers` (с fallback на `users`), факт существования руководителя не зависит от `count >= 1`.
 - Обычный `users` остаётся визуально отфильтрованным набором: сотрудники с дробной занятостью не появляются в обычных employee columns; `staffCount`/`vacancyCount` не изменились; исходное API-дерево не мутируется.
 - Mapping дирекций переведён на стабильный `department_guid` (название — только fallback/диагностика): «Дирекция по финансам и отчетности» снова привязана к Лукьянову, переименование подразделения при сохранении GUID не ломает hierarchy. Единый helper `matchesConfiguredDepartment` для всех executives.

## 2.24.0 (2026-08-27)
 - Верхнеуровневая управленческая структура Холдинга (CR-013): при выборе корня «Холдинг LEGENDA» диаграмма строится по управленческой иерархии — Селиванов, его персональный ассистент и три верхних руководителя (Лукьянов, Винник, Клюев), под которыми распределены дирекции. «Администрация» используется как источник людей верхнего управления и не отображается как обычная дирекция.
 - Проекция реализована отдельным модулем `holding-leadership.js` с единой конфигурацией верхнего руководства (руководители, дирекции, прямые подчинённые, ассистент Селиванова). Селиванов больше не дублируется hardcode: имя/должность берутся из конфигурации.
 - Дедупликация руководителей по email («Основное место работы» имеет приоритет); прямые подчинённые Клюева (Сойдан, Кириллов) отображаются под ним как сотрудники; исходное API-дерево не мутируется, численность не изменяется.
 - Проекция работает в режимах AS IS / TO BE / Изменения (для Changes люди верхнего управления берутся из working tree), применяется в обоих экранных рендерерах и в PDF-экспорте. Нераспределённые подразделения выводятся под корнем в fallback-группе с предупреждением.

## 2.23.0 (2026-08-27)
 - Дефолтное сворачивание структуры Холдинга до уровня Дирекций (CR-012): при выборе корня организации («Холдинг LEGENDA») диаграмма по умолчанию показывает только сам Холдинг и его непосредственные дирекции. Все дочерние уровни, сотрудники и вакансии внутри дирекций скрыты до раскрытия пользователем.
 - Правило применяется только к фактическому корню всей организации (структурный маркер synthetic-root, без анализа текста названий). Отдельно выбранная Дирекция по-прежнему открывается целиком по существующей логике.
 - Дефолтное сворачивание работает во всех режимах (AS IS / TO BE / Изменения) и в обоих экранных рендерерах (обычный и Compact A4); initial fit считается только по видимым узлам. При повторном выборе Холдинга снова применяется дефолтное состояние.
 - Раскрытие конкретной дирекции сохраняет текущий zoom/pan и визуальный фокус (механизм CR-011); PDF-экспорт не изменён.

## 2.22.0 (2026-08-27)
 - Сохранение zoom, pan и визуального фокуса при collapse/expand экранной диаграммы (CR-011): текущий viewport transform теперь переживает структурный rerender вместо сброса к default fit. Пользователь остаётся в том же масштабе и на том же участке схемы при сворачивании/разворачивании ветвей.
 - Восстановление viewport реализовано через общий viewport-хелпер (screen-viewport.js): добавлены `getTransform()`, `restoreTransform(transform, {anchor})` и `projectPoint()`. Оба экранных рендерера (Unified и Compact A4) используют один механизм.
 - При collapse/expand сохраняется экранная позиция карточки, по которой выполнили действие (anchor-preserving update): translate корректируется так, чтобы центр карточки остался на прежнем экранном месте даже при изменении геометрии layout.
 - `fit()` по-прежнему выполняется только при первичной загрузке диаграммы, выборе нового root и явном действии пользователя; после collapse/expand автоматический fit не вызывается.

## 2.20.0 (2026-08-25)
 - Изменено назначение опции «Выгружать PDF без фамилий» (CR-003-02): при включении экспорт формирует компактную ролевую структуру — сотрудники подразделения агрегируются по должностям («Специалист ×5»), индивидуальные карточки не создаются.
