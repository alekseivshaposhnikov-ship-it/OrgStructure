# Changelog

## 2.22.0 (2026-08-27)
 - Сохранение zoom, pan и визуального фокуса при collapse/expand экранной диаграммы (CR-011): текущий viewport transform теперь переживает структурный rerender вместо сброса к default fit. Пользователь остаётся в том же масштабе и на том же участке схемы при сворачивании/разворачивании ветвей.
 - Восстановление viewport реализовано через общий viewport-хелпер (screen-viewport.js): добавлены `getTransform()`, `restoreTransform(transform, {anchor})` и `projectPoint()`. Оба экранных рендерера (Unified и Compact A4) используют один механизм.
 - При collapse/expand сохраняется экранная позиция карточки, по которой выполнили действие (anchor-preserving update): translate корректируется так, чтобы центр карточки остался на прежнем экранном месте даже при изменении геометрии layout.
 - `fit()` по-прежнему выполняется только при первичной загрузке диаграммы, выборе нового root и явном действии пользователя; после collapse/expand автоматический fit не вызывается.

## 2.21.1 (2026-08-26)
 - Исправлено перекрытие названия подразделения и должности руководителя/ролей в компактном PDF (CR-003-03-fix-height): вертикальная геометрия карточки теперь строится последовательно title → titleHeight → gap → manager → gap → roles с учётом фактического количества строк названия (через тот же механизм переноса текста).
 - Высота department-card в ролевом режиме рассчитывается по фактическому содержимому (включая перенос названия на 2–3 строки) и согласована между renderer и Unified Layout (node.height) — линии и следующие ряды не пересекаются с увеличенной карточкой.
 - Доступная ширина названия учитывает count badge справа, поэтому badge не перекрывает title.

## 2.21.0 (2026-08-25)
 - Визуальная доработка Compact Role PDF (CR-003-03): роли выровнены в двухколоночную таблицу «должность / count», счётчики ролей и общая численность подразделения оформлены компактными badge; header и роли разделены тонким divider.
 - Уплотнены вертикальные отступы внутри карточки и горизонтальные/вертикальные gaps между карточками ролевого режима; connector lines стали визуально легче.
 - Page-fit в ролевом режиме использует фактический bounding box контента — схема занимает большую часть листа, итоговый масштаб и читаемость текста выше.
 - В subtitle ролевого экспорта вместо «без фамилий» используется «по должностям».

## 2.20.1 (2026-08-25)
 - Обновлена реализация ролевого PDF (CR-003-02): при включённой опции «Выгружать PDF без фамилий» роли теперь встроены **непосредственно в карточку подразделения** (подразделение + должность руководителя + агрегированный ролевой состав в одной карточке). Отдельный блок «Сотрудники подразделения» и NODE_EMPLOYEES не создаются — они не занимают место в геометрии.
 - Высота department-card в ролевом режиме зависит от числа уникальных должностей (динамическая высота); пустой ролевой блок и разделитель не выводятся, если собственных сотрудников кроме руководителя нет.
 - Вакансии учитываются отдельно от занятых позиций («+N вак.»), руководитель не дублируется в списке ролей, дочерние подразделения остаются отдельными узлами схемы.
 - Соединительные линии существуют только между подразделениями.

## 2.20.0 (2026-08-25)
 - Изменено назначение опции «Выгружать PDF без фамилий» (CR-003-02): при включении экспорт формирует компактную ролевую структуру — сотрудники подразделения агрегируются по должностям («Специалист ×5»), индивидуальные карточки не создаются.
 - Руководитель не дублируется в списке ролей; вакансии учитываются отдельно («+N вак.»); дочерние подразделения не смешиваются с ролями; иерархия и Unified Layout не меняются.
 - Высота employee-блока определяется числом уникальных должностей, а не числом сотрудников — типовые дирекции становятся заметно компактнее.
 - Бизнес-сортировка `positionWeight` / `sortUsersByPositionLevel` вынесена в общий модуль `core/utils/position.js` и переиспользуется в api.js, scenario-manager.js и PDF-экспорте.

## 2.19.1 (2026-08-25)
 - Исправлен PDF-экспорт при выключенном флаге «Показывать вакансии» (CR-003-01): текущее состояние UI `showVacancies` теперь передаётся в `computeUnifiedLayout()` при построении PDF. Ранее PDF всегда экспортировался с вакансиями, т.к. layout строился со значением по умолчанию.

## 2.19.0 (2026-08-25)
 - PDF-экспорт обычной диаграммы переведён на единый Unified Layout (CR-003): экран и PDF используют один `computeUnifiedLayout()` — один источник координат узлов, строк, parent-child связей и employee columns.
 - Удалён дублирующий PDF-алгоритм построения схемы (собственный subtree layout, person grid, повторный расчёт уровней/строк). PDF renderer теперь только отрисовывает готовый layout с единым масштабом, центрированием и сохранением header.
 - PDF использует ту же конфигурацию размеров карточек, что и экран (CR-003 §17): изменённая «Ширина карточек» теперь учитывается и в экспорте.
 - Connector lines строятся на основе `layout.edges`.

## 2.18.0 (2026-08-21)
 - Исправлен лимит масштабирования экранной диаграммы (CR-011): максимальное увеличение увеличено с 300% до 10 000% (100x), минимальный масштаб снижен до 2% (0.02). Теперь можно приближать выбранную ветку или отдельную карточку практически без ограничений и сильнее отдалять большие схемы.
 - Единый диапазон zoom для обычного рендера и Compact A4: константы MIN_ZOOM_SCALE / MAX_ZOOM_SCALE задаются в общем viewport-хелпере (screen-viewport.js), без дублирования scaleExtent по рендерам.
